# 学生身份匹配与我的考试

设计规则已整理发布为 [Issue #8](https://github.com/MingYuanWei1/calendar/issues/8)，完整实施规格见 [student-exam-matching-spec.md](student-exam-matching-spec.md)。本文保留讨论中的决定摘要；功能已实现，启用步骤见 [student-matching-setup.md](student-matching-setup.md)。

## 已确认决定

- 学校邮箱前缀由两位毕业年份和姓在前、名在后的中文姓名拼音组成，例如 2028 届王小明为 `28wangxiaoming`。学校毕业月份为七月。
- 建立学生表，使用固定内部学生 ID。邮箱匹配字段可修正，不用邮箱前缀作为学生主键；考试座位安排关联内部学生 ID。
- LLM 或人工输入学生信息后，整理学生记录及邮箱匹配信息。推算的邮箱信息不代表已验证的实际邮箱。
- 身份匹配冲突提示管理员核实并解决，不静默合并冲突学生。
- 按账号、考试批次分别初始化一次自动勾选，已有用户也适用；之后用户可自由更改选择。没有可匹配的已发布座位时暂缓初始化；主动清空选择不视为尚未初始化，再次登录不覆盖用户选择。
- 初始化后新增关联考试时，弹窗提示“有新的关联考试”，提供“一键导入”“选择考试导入”“取消”三个选项。“选择考试导入”允许勾选想要导入的场次；不未经用户选择自动补选。
- 考试详情保留全部考场及座位信息供正常查看。有本人该场考试的座位信息时，初始打开本人所在考场并高亮本人座位；不再隐藏其他考场。没有本人座位时按正常方式展示。
- 考试批次明确所属学年，可根据考试日期预填并由管理员修改。毕业年份 = 学年结束年份 + (12 − 年级)。
- 学生年级优先从原表提取，单年级场次可继承，无法确定时由管理员补充。班级标记如 `10.5` 需按明确的格式规则解析为十年级五班，不由模型自行猜测。
- 管理端展示并允许修正拼音及推算邮箱；学生端默认只显示中英文名。
- 新关联考试弹窗取消或部分导入后，本次展示过的场次不再自动弹窗；保留“导入关联考试”入口。出现新的关联场次才再次提醒，用户主动取消勾选的场次不作为新增场次反复提醒。
- 已有用户首次初始化时保留原有手动勾选，再追加关联考试；之后不自动覆盖该批次选择。
- 自动关联的座位发生更改或删除时，用户端弹窗提示；用户已自动勾选的考试新同步到本人座位时，也弹窗提示。
- 设置“学生管理”入口，展示冲突姓名、班级、毕业年份及推算邮箱，允许管理员纠正信息、填写实际邮箱或确认合并重复学生。未解决身份冲突的记录不自动关联账号，但不阻止其他座位正常发布。
- 邮箱不符合学校邮箱规则的账号直接跳过自动同步校验，保留原有手动选择功能。
- 座位提醒覆盖当前“我的考试”中的所有场次，包括手动勾选的场次；用户取消勾选后不再提醒该场次座位变化。座位删除只更新座位信息并提示，不自动取消考试勾选。
- 关联及座位变更提醒以已发布结果为准，草稿修改不触发。新增座位提示“已分配座位”；变更显示原位置和新位置；删除提示“座位安排已移除”。暂时撤下座位表显示“座位安排暂不可用”，不当作已删除学生分配；不可用时不显示旧座位为当前有效座位。
- 进入考试页、切换批次、页面重新回到前台时检查更新；页面持续打开时每分钟检查一次。同一批次多场座位变化合并成一个弹窗，用户确认后不重复提示，后续有新变化才再次提醒。

## 配置与实现约束

- `xx.edu.cn` 是讨论中的示例域名，启用匹配时需使用学校实际域名，不将任意教育域名视为本校邮箱。
- 已初始化、用户已看过的关联考试、已确认的座位变化需要分别记录。空选择不能代表未初始化，重新发布相同座位也不能造成重复提醒。
- 管理员填写的实际邮箱仍遵循学校邮箱校验规则；未取得可靠邮箱、规则不符或身份冲突时不自动绑定学生。

## 实施前检查的兼容性约束

- 当前登录身份没有保存邮箱，需补充可靠的学校邮箱来源；仍保留现有稳定账号标识。
- 当前座位记录没有学生 ID 或独立年级；场次适用年级可有多个，班级是自由文本。
- 当前“我的考试”按账号、批次保存手动选择，座位表独立发布；修改考试安排可能撤下已发布座位。
