# 学校公共校历需求

## 已确认

- 主要受众：学生。
- 平台：网站；以电脑端月历查看为主。
- 事件范围：节假日、各学部期中期末考试、比赛、活动、选课截止日等公共事项。
- 不包含个人事件或个人日常课程。
- 浏览端面向所有人，无需登录。
- 平台仅展示信息，不承办报名；可展示报名表单链接或二维码。
- 管理员在后台添加事件。
- 参考 Google Calendar 的大体布局与点击查看事件详情的交互。
- 本轮交付：产品方案与界面设计稿。
- 工作顺序：需求访谈并确认共同理解，再做 GitHub 原型调研，最后开始设计。
- 公开可见与适用范围分开：允许面向特定学部的公共事件，排除个人事项。
- 默认展示全部事件；支持类型、学部筛选和标题搜索，学生可筛选“全校＋自己的学部”。
- 颜色代表事件类型，学部使用文字标签。
- 支持定时、全天、跨日事件与截止时间；首版不做重复规则。地点可为空。
- 点击事件打开右侧详情面板，保留月历上下文。
- 必填字段：名称、时间、类型、适用范围。
- 选填字段：地点、说明、主办方、海报、报名链接或二维码。首版不加入联系人和附件。
- 月历每格展示约 3–4 条事件，其余通过“还有 N 项”展开当天列表；跨日事件使用连续横条；截止日有文字标识。
- 后台首版不做审核；管理员角色与维护范围尚待确认。
- 取消事件保留记录并标注“已取消”；改期事件移至新日期，详情显示原时间及更新时间；删除用于误录内容。
- 学部划分：小学部、初中部、高中部。
- 界面默认简体中文，支持切换英文。
- 设计三套简约视觉方案：一套参考 Google Calendar，另外两套自由探索。
- 管理员可维护全部事件，不按学部分配编辑权限。
- 浏览视图为月历与日程列表，首版不加入周视图。
- 以电脑端设计为主，补充手机端列表和详情设计。
- 使用学校所在地时区、周一起始、公历；节假日由管理员录入，不自动导入。
- 交付产品需求文档、GitHub 参考项目对比与静态 HTML 设计稿。
- 设计覆盖月历、事件详情、当天溢出列表、筛选结果、后台事件列表、新增／编辑页面及手机端关键页面。

## 已确认的默认处理

- 学校名称和校徽使用占位内容；所在地尚未提供，设计中以“学校当地时间”表示，不绑定具体时区。
- 中英切换覆盖界面；事件内容支持分别填写中文与英文，缺少译文时展示已有内容，不做自动翻译。
- 事件适用范围可选全校或一个／多个学部。
- 后台登录，支持保存草稿、预览和直接发布。
- 三套方案先以同一组事件展示月历与详情，选定一套后扩展其余页面。
- 两套自由探索方案拟为“校园公告”和“轻盈分区”，与 Google Calendar 风格方案对比。
- GitHub 调研侧重可参考的日历交互、展示布局及管理表单，记录来源与许可证，不直接决定采用完整开源系统。
- Logo 放置在左上角，现阶段使用明确的占位符。
