# 考试安排使用与部署

## 入口

- 学生端：`/exams.html`。不登录可按批次、学部、年级浏览并下载整个批次的考试 PDF。
- 后台：`/exams-admin.html`，使用现有校历管理员账号。Microsoft 登录不会授予编辑权限。
- 原校历顶部增加「考试安排」，考试类型事件详情也有入口。

## Microsoft Entra ID 单组织登录

在学校租户中注册 Web 应用，仅选择本组织目录内账户。设置 Web 重定向 URI 为 `${APP_ORIGIN}/api/school/callback`，例如 `https://calendar.school.example/api/school/callback`。本地测试配置必须与本地 APP_ORIGIN 完全一致。

在服务器 `.env` 中设置：

```dotenv
MICROSOFT_TENANT_ID=学校目录的租户UUID
MICROSOFT_CLIENT_ID=应用程序客户端UUID
MICROSOFT_CLIENT_SECRET=应用客户端密钥的值
```

不要把密钥写入前端文件或提交到 Git。重启服务后登录生效。本实现请求 `openid profile`，使用授权码与 PKCE，校验 state、nonce、签名、issuer、audience、tid、有效期；按租户与 Microsoft 用户对象 ID 保存勾选。没有租户配置时不提供模拟登录，只展示公开安排与配置提示。

真实 Microsoft 登录、组织的条件访问规则和重定向配置必须由学校提供配置后再端到端验收。程序化身份校验测试与隔离环境中的已登录功能测试不等同于真实 SSO 验收。

参考：[Microsoft OIDC 文档](https://learn.microsoft.com/en-us/entra/identity-platform/v2-protocols-oidc)。

## 管理流程

1. 新建考试批次，填写起止日期（最多 366 天）。
2. 添加教室，设置每个教室的排数和列数（每方向 1–40）。
3. 添加考试场次：科目/课程/级别、学部、年级、日期、起止时间、教室；固定编号用于关联座位和学生勾选。
4. 保存草稿，检查「预览并发布考试安排」。保存不会改变已发布版本。
5. 下载该批次的 Excel 模板，填写「座位数据」表，一行一个座位：考试编号、教室、排、列、班级、中文名、英文名。参考页列出可用考试编号和教室。班级必填，姓名至少填写一种。无需学号、邮箱或独立座位编号。
6. 上传后先检查预览及错误；确认会替换本批次全部草稿座位，不追加。网页可新增、编辑、移除草稿座位，保存后再独立预览并发布。
7. 不同场次可在一个教室混考。同一日期、教室、排、列不能在重叠时间段被重复占用。座位图通过时段选择查看该时刻全教室名单。

考试的时间、教室或取消状态修改后重新发布，会撤下原座位表，必须核对后重新发布座位。已发布场次不能移除，使用取消以保留个人选择。发布与编辑带版本检查，遇到其他窗口修改会返回冲突，不静默覆盖。

## 学生操作

登录后逐场或批量勾选本周考试。选择自动保存在账号下，不是学校报考名单，也不依赖座位表。我的考试显示整个批次的已选场次（按周浏览），不被学部、年级筛选截断。同时间已选场次给出冲突提示，仍可保存。

登录后可以查看全部已发布名单。仅公开考试接口和 PDF 不包含姓名。PDF 只导出整个批次的 schedule，可选当前学部/年级或我的考试；含日期、时间、考试名称、学部/年级和教室，保留取消/变更标记与生成时间，不含座位图或学生名单。

## 示例和备份

`npm run samples:exams` 创建带「示例」标记的虚构批次和虚构座位，不覆盖已经存在的同名示例。生产数据与考试数据同存 `.data/calendar.sqlite`，沿用项目备份流程。

## 验证

`npm run typecheck` 检查前端；`npm test` 包含考试发布隔离、座位访问、账号选择隔离、改期与取消保留选择、导入冲突、PDF、Microsoft 身份声明校验。浏览器已在隔离数据库中验证勾选刷新保留、跨学部个人考试、混考时段、后台草稿/发布及 Excel 导入确认。
