# 学校公共校历 · 产品方案

状态：需求已确认；已选 C「轻盈分区」，增加左侧学部与事件类型筛选栏。学校名称、Logo、真实时区与正式事件数据待提供，不阻碍方向稿。

## 产品目标

学生在公开网站快速回答：学校最近有什么事件，何时发生，在哪里，是否适用于自己，以及应去哪里获取参与信息。公共浏览不需要账号，网站不承办报名。

## 信息结构

- 浏览端：月历、日程列表、事件详情、当天事件列表、类型与学部筛选、标题搜索、中英文切换。
- 管理端：登录、事件列表、新增／编辑、草稿预览、发布、取消、改期和删除误录。
- 电脑以月历为默认；手机以日程列表为默认。详情在电脑侧面板打开，在手机独立全屏层打开。

## 事件信息

| 字段 | 规则 |
| --- | --- |
| 名称 | 必填；支持中文、英文。至少一种语言有值；缺少当前语言时回退到已有内容 |
| 类型 | 必填：考试、假期、比赛、活动、截止日；文字与颜色同时表达 |
| 适用范围 | 必填：全校，或小学部／初中部／高中部的一个或多个。全校与具体学部互斥 |
| 时间 | 必填；定时、全天、跨日或截止时间。按学校当地时间填写与显示 |
| 地点 | 选填；假期及截止日无需填写，未填时省略该行 |
| 说明 | 选填，支持中英文；无自动翻译 |
| 主办方 | 选填；支持中英文 |
| 海报 | 选填；详情中查看，不占月历网格空间 |
| 报名入口 | 选填：外部表单链接或二维码，可并存；清楚说明跳转至外部渠道 |
| 状态 | 草稿、已发布、已取消；改期为变更提示，不是独立发布状态 |
| 更新时间与原时间 | 供学生识别信息变更；改期后显示原时间与当前时间 |

## 浏览规则

1. 默认显示全部类型、全部学部的公开事件。筛选“初中部”时，包含面向初中部的事件及全校事件。类型、学部与标题关键词共同生效。
2. 月历以周一开始，保留周末。跨日事件按连续横条展示；超过一周时在下一行继续。
3. 每格控制在约 3–4 项，跨日条计入可见数量，剩余用“还有 N 项”展开。展开列表包含该日所有符合当前筛选的事件。
4. 截止日显示“截止”与具体时间；颜色不是唯一识别方式。取消事件保留取消标识，改期事件在新日期显示且详情保留原时间。
5. 点击事件打开详情，不跳出当前月历。关闭后保留日期、筛选及浏览位置。
6. 月份导航、回到今天、月历／日程切换不清除筛选。空结果区提示调整条件或重置。
7. 语言切换不更改日期和筛选；事件内容优先当前语言，缺失时回退到已填写内容。

## 管理流程

管理员登录 → 查看全部事件 → 新增／编辑 → 保存草稿或预览 → 发布。

所有管理员权限相同。草稿仅后台可见，无审核步骤。发布时校验名称、类型、适用范围及时间；结束时间不得早于开始时间。允许时间冲突，因为不同学部可同时发生不同事件。

管理员可取消已发布事件并填写说明；公共校历保留取消记录。改期需保留原时间与更新时间。删除用于误录，设计中提示操作影响并提供确认。若事件真实举行过，不用删除代替归档，过去事件仍能通过日期导航查阅。

## 视觉方向与本轮交付

参考 [GitHub 调研](github-research.md)，以同一组 2026 年 9 月虚构事件制作 [三套 HTML 方向稿](../designs/index.html)。左上角为 Logo 占位；三套都包括月历和详情，并提供列表、筛选、溢出、中英文及手机排版的演示，帮助比较设计。

这些交互仅切换静态示例状态；没有真实账号、数据存储或报名提交。设计稿中的“今天”固定为 2026-09-19，避免跨天改变评审样本。节假日示例不代表任何地区真实安排。

后续沿用已选定的 C＋侧栏方向，扩展完整的后台、登录、编辑表单、预览与异常状态设计。海报与二维码展示状态也在该阶段补齐；当前三套详情以相同的文字与外部报名入口比较阅读体验。

## 后续设计验收重点

- 电脑月历信息可扫读，学部和事件类型不混淆。
- 长标题、跨日事件、同一天超过四项时仍可获取完整信息。
- 时间、地点、适用范围在详情首屏可找到。
- 小屏无需横向拖动七列月历；详情可关闭并返回原列表。
- 中英文均不遮挡控件或截断关键时间；颜色之外有文字状态。
- 键盘可访问筛选与事件，弹层具备清楚的标题、关闭入口和可见焦点。
