# 0001 后台提取任务

确认于 2026-10-11。

## 背景

座位表与考试安排的 AI 提取原本是一次流式 HTTP 请求：结果只沿连接传回浏览器，服务端不保存。关闭弹窗会中止请求；关闭页面时 Cloudflare 取消 Durable Object 中的 LLM 子请求；本地 Node 即使跑完，结果也因连接已断而丢弃，白白消耗一次调用。

## 决定

- 座位表提取与考试安排提取改为**提取任务**，挂在考试批次上，所有管理员可见。机制通用，通知提取日后接入。
- 同一批次同时最多一个运行中的任务；要重来须先取消。关闭弹窗或页面只是离开，任务继续；“取消提取”才会停止。
- 上传文件上限 10 MB，按 512 KB 分块存入数据库（Durable Object SQLite 单值上限 2 MB）。文件与结果保留 7 天，导入后立即清理。
- 发起时即读取文件并生成模型请求（文件无效当场报错，不计限额），之后由 **Cloudflare Workflows** 执行两步：调用 LLM 提取 → 整理结果（核对身份、教室变化）。整理失败自动重试 3 次；LLM 步骤仅在网络错误或 5xx 时重试 1 次，重试前清空已写入条目；超时或模型空回复直接失败，由管理员手动重试。Workflow 通过 Durable Object 的 RPC（`extractJob`）读写任务。本地 Node 在进程内执行同一流程（`server/extract-run.mjs`），共用任务表与接口。
- AI 调用限额只在发起或手动重试时计一次，自动重试不计。
- 提取出的条目边跑边节流写入任务表（每秒一次，至少每 10 秒一次心跳；超过 4 分钟无心跳视为中断）；页面每 2 秒轮询新增条目。重试会以当前草稿重新生成请求。重新打开可看到已提取部分，失败时可使用已提取部分。
- 任务期间草稿可被修改；导入时以当前草稿重新核对身份，并按当前草稿合并（新增与修正）。
- 完成后只在批次页与导航标记，不发邮件或推送。

## 取舍

- 未用 `ctx.waitUntil`：最多 15 分钟且无重试；Workflows 步骤时长不受限、可重试，但需要新增绑定，并通过 Durable Object stub 回写任务表。
- 未用 alarm：至少执行一次，可能重复调用 LLM。
- 轮询而非重连 NDJSON 流：无状态，更适合经 nginx 中转。
