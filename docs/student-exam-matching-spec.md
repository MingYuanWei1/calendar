# 学校邮箱匹配学生、初始化我的考试与座位变更提醒

## Problem Statement

学生登录后仍需逐场寻找并勾选自己的考试，再从多个考场的座位表中寻找自己。管理员通过 LLM、标准表格或手工输入的座位记录只有姓名和班级等信息，尚未形成跨场次稳定的学生身份。考试和座位安排更新后，学生也无法可靠地区分新增关联考试、座位移动、分配删除与座位表暂时撤下。

学校学生邮箱由两位毕业年份、姓在前名在后的姓名拼音和学校域名组成。这使自动关联成为可能，但拼音重名、信息缺失和姓名识别错误必须显式处理，不能将推算邮箱当成学生的永久编号。

## Solution

后台整理统一学生表，以固定学生 ID 关联各场考试座位，通过学校邮箱找到登录账号对应的学生。每个考试批次首次有可用匹配时自动追加关联考试，此后保留用户自主选择。新增关联考试提供导入弹窗；已选择考试的本人座位变化提供独立、可确认且不重复的提醒。

考试详情保留所有考场可查看，有本人座位时默认打开所在考场并高亮。管理员可以核对拼音、纠正邮箱和解决身份匹配冲突。邮箱不符合规则的账号直接跳过自动同步，继续使用现有手动功能。

## User Stories

1. As an 学生, I want a 登录学校账号后匹配本人学生记录的功能, so that 我不必重复输入姓名查找考试。
2. As an 学生, I want a 每个考试批次各初始化一次的自动勾选功能, so that 新批次也能自动找到我的考试。
3. As an 已有用户, I want a 保留原有勾选并追加关联考试的初始化方式, so that 已做出的选择不会丢失。
4. As an 学生, I want a 初始化后自由添加或取消考试的功能, so that 我的考试符合个人关注范围。
5. As an 学生, I want a 主动清空后仍保持为空的考试列表, so that 再次登录不会替我重新勾选。
6. As an 学生, I want a 没有已发布本人座位时暂缓初始化的机制, so that 数据就绪后仍能完成首次匹配。
7. As an 学生, I want a 新增关联考试弹窗, so that 我能知道又有哪些考试与我有关。
8. As an 学生, I want a “一键导入”选项, so that 我能一次加入全部待导入关联考试。
9. As an 学生, I want a “选择考试导入”选项, so that 我可以只勾选想加入的场次。
10. As an 学生, I want a “取消”选项, so that 我可以不修改当前选择。
11. As an 学生, I want a 取消或部分导入后不重复弹出相同考试的行为, so that 我不会被反复打扰。
12. As an 学生, I want a 常驻“导入关联考试”入口, so that 我能稍后重新选择此前忽略的考试。
13. As an 学生, I want a 不把主动取消的场次重新当作新增考试的规则, so that 系统尊重我的选择。
14. As an 学生, I want a 默认打开本人考场的考试详情, so that 我能快速确认考试地点。
15. As an 学生, I want a 高亮本人座位的座位表, so that 我能快速找到具体位置。
16. As an 学生, I want a 仍可切换查看其他考场及全部座位的功能, so that 自动定位不会限制正常浏览。
17. As an 学生, I want a 未找到本人座位时仍正常显示考场的详情页, so that 我仍能查看已发布信息。
18. As an 学生, I want a 当前勾选考试首次分配本人座位时的提醒, so that 手动或自动加入的考试都不会漏掉座位消息。
19. As an 学生, I want a 展示原位置和新位置的座位变更提醒, so that 我清楚应前往哪里。
20. As an 学生, I want a 座位分配被删除时的提醒, so that 我知道原座位已失效。
21. As an 学生, I want a 删除座位后仍保留考试勾选的行为, so that 我仍能关注该场考试。
22. As an 学生, I want a 区分暂时撤下座位表和删除本人分配的提示, so that 我不会把待更新误解为无需应考。
23. As an 学生, I want a 只依据已发布结果的提醒, so that 管理员草稿编辑不会造成误报。
24. As an 学生, I want a 取消勾选后停止该场次座位提醒的行为, so that 提醒范围与我的考试一致。
25. As an 学生, I want a 同批次多场座位变化合并的弹窗, so that 我能集中查看变化。
26. As an 学生, I want a 确认后不重复、后续变化仍提醒的机制, so that 我既不会漏看更新也不会重复处理。
27. As an 学生, I want a 进入页面、切换批次、返回前台及持续打开时检查更新的功能, so that 我可以及时看到已发布变更。
28. As an 不符合邮箱规则的用户, I want a 自动跳过同步且保留手动功能的行为, so that 我仍能正常使用考试页面。
29. As an 管理员, I want a 从 LLM、标准表格和手工输入整理学生记录的统一流程, so that 不同输入来源都能关联座位。
30. As an 管理员, I want a 不随姓名、班级或邮箱修正变化的学生编号, so that 学生历史座位关联保持稳定。
31. As an 管理员, I want a 明确并可修正考试批次学年的功能, so that 历史和暑期考试不会按登录日期算错届别。
32. As an 管理员, I want a 从明确年级推算毕业年份和邮箱前缀的功能, so that 我不必逐个填写常规学生邮箱。
33. As an 管理员, I want a 缺失或不确定年级待补充的处理方式, so that 系统不会猜测学生身份。
34. As an 管理员, I want a 查看并修正拼音及实际邮箱的入口, so that 多音字、提取错误等问题可以纠正。
35. As an 管理员, I want a 汇总姓名、班级、毕业年份和邮箱冲突的学生管理入口, so that 我能核实身份匹配冲突。
36. As an 管理员, I want a 纠正信息、区分学生或确认合并重复学生的能力, so that 同音学生不会被静默合并。
37. As an 管理员, I want a 未解决冲突不自动关联账号、但不阻止其他座位正常发布的规则, so that 局部数据问题不会拖延整体发布。
38. As an 学生, I want a 默认保持中英文姓名展示的座位图, so that 拼音核对信息不会挤占学生端界面。

## Implementation Decisions

- 学生实体使用固定内部 ID；学校邮箱及其匹配字段可修改。账号继续使用现有稳定登录标识，不以邮箱前缀替换账号主键。学生身份与账号身份分离，考试座位安排引用学生 ID。
- 学校邮箱规则为两位毕业年份加姓、名连写拼音；例如 2028 届王小明对应前缀 `28wangxiaoming`。仅匹配配置的本校域名；示例域名不能作为真实部署值。登录邮箱来自可信认证结果，不能仅凭客户端提交邮箱建立绑定。缺少可靠邮箱或格式不符时跳过自动同步。
- 毕业年份按“所属学年结束年份 + (12 − 年级)”推算，保留完整年份，邮箱前缀取末两位。例如 2026–2027 学年十年级对应 2029 届。批次学年可按考试日期预填并由管理员修正，不使用访问当天的年份重新推断历史身份。
- 年级范围为 1–12，优先读取原表明确年级；单年级场次可继承，跨年级场次不能直接推定个人年级。班级如 `10.5` 仅按明确格式解析为十年级五班；缺失或矛盾由管理员补充，不靠 LLM 猜测。班级、年级属于具体学年，不用作永久学生编号。
- LLM 提取、标准表格导入及人工编辑进入一致的学生整理流程。重复输入应复用可唯一确认的学生，不能每次导入都新增学生或把相同拼音强行合并。缺中文姓名不根据英文昵称臆造拼音，保留原始姓名供管理员核实。
- 学生管理支持查看冲突、修正姓名/拼音/毕业年份/邮箱及确认合并重复学生；修正或合并保留相关座位的身份连续性。实际邮箱修正用于替代推算值，仍受本校邮箱规则约束；冲突未解决的学生不自动关联账号。现有管理员权限边界继续适用。
- 考试与座位沿用现有独立草稿、预览、发布流程。自动关联只使用已发布结果；整理草稿身份不应提前改变学生端的当前有效座位。身份修正造成已发布关联变化时，同样遵守选择保留与变更提醒规则。
- 按账号和考试批次持久化初始化状态。首次存在可用关联时，将关联考试与已有选择取并集，再标记完成；没有可用关联则暂缓。后续登录、刷新、座位发布不能覆盖用户选择。主动清空与未初始化是不同状态。
- 初始化后的新增关联考试不自动加入；弹窗标题为“有新的关联考试”，操作为“一键导入”“选择考试导入”“取消”。导入仅追加用户选择的有效场次，保留其他勾选。
- 已展示并处理过的关联场次单独记录。取消或部分导入后，这次弹窗中的其他场次不再自动提示；用户手动取消的场次也不重新成为新增候选。“导入关联考试”入口允许用户后续主动导入。座位更新或相同数据重新发布不能被当作新增考试。
- 当前“我的考试”的所有场次都纳入座位提醒，无论手动还是自动勾选；取消勾选即退出提醒范围。本人座位新增提示“已分配座位”，变化展示前后位置，删除提示“座位安排已移除”。座位删除或不再属于本人不自动取消考试选择；考试场次本身的删除继续沿用已有行为。
- 区分座位表暂时不可用与已发布结果中移除学生分配。暂时撤下显示“座位安排暂不可用”，不把旧座位展示成当前有效位置，不把整表缺失批量误报为删除。重新发布后根据新的有效结果恢复展示或提醒实际变化。
- 考试详情仍允许查看所有已发布考场和座位；有唯一有效的本人座位时默认定位其考场并高亮。无本人座位或身份冲突时正常浏览，不高亮推测位置。该功能不改变既有座位访问权限，也不在学生端追加拼音行。
- 同一批次座位变化合并成弹窗，确认状态按账号持久化。用户确认过的变化不重复；相同数据重发不制造新提醒，后续真实变化仍可提醒。确认必须指向用户实际看到的变化，不能把弹窗打开后发生的新变化一并标为已读。
- 进入考试页、切换批次、返回前台时检查；页面持续打开时每分钟检查一次。保持账号和批次隔离，异步旧响应不能覆盖已切换页面或其他账号的状态；检查失败不能当作座位删除。
- 优先扩展现有认证、考试导入/发布、座位查询和个人选择接口；补充学生管理、关联考试导入及变更确认能力。接口需要区分初始化状态、未处理的关联考试、当前本人座位、不可用状态和待确认变化，具体路由与存储布局由实施时决定。导入、初始化与确认重复请求应保持相同用户可见结果。

## Testing Decisions

- 首选现有应用 HTTP 集成测试入口，以临时数据库运行真实应用，通过管理员和学生会话调用外部接口。重点测试“输入学生与座位 → 发布 → 登录匹配 → 查询/修改我的考试 → 发布变化 → 读取并确认提醒”的完整行为，而非内部函数调用次数、SQL 布局或拼音库实现。该测试入口方案已获用户确认：现有 HTTP 集成测试加浏览器验收。
- 既有先例包括考试发布、私人座位访问、账号隔离、手动选择持久化及座位撤下的集成场景；认证和角色权限场景；表格提取与输入校验场景。沿用这些测试设施，不新增一套平行应用测试框架。
- 验证 2026–2027 学年十年级王小明匹配 `29wangxiaoming`，十二年级对应 `27`、一年级对应 `38`；历史批次不受当前日期影响，暑期由批次学年确定。覆盖多班级格式、跨年级场次、缺失姓名/年级、同音异名、邮箱缺失/规则不符/外校域名及管理员更正后恢复匹配。
- 验证重复导入不制造重复学生；不同学生身份冲突不合并、不错误绑定；管理员修正和显式合并后关联稳定；未经授权的用户不能管理学生。可在认证提供方或 LLM 外部服务边界使用受控响应，不依赖真实学校凭据或实时模型输出。
- 验证按账号、批次仅初始化一次；已有勾选保留；无座位时暂缓；后续发布可初始化；用户清空后仍为空；账号及批次之间互不影响。
- 验证全部导入、部分导入、取消、常驻入口重试以及手动取消场次不反复提示。重复检查和重复提交不得重复追加或吞掉后续新增场次。
- 验证手动/自动勾选场次的座位新增、移动、删除、暂时撤下、重新发布与身份修正；取消勾选停止提醒，座位删除保留考试选择，草稿不提醒、相同内容重发不提醒。网络失败不能产生删除消息。
- 验证同批聚合、确认后跨刷新不再提示、确认后新变更仍提示，以及读取到确认期间发布新变化时不丢提醒。
- 对 HTTP 无法证明的展示行为，沿用项目现有真实浏览器验收方式，从可见控件验证三个导入选项、选择列表、默认考场、本人高亮、其他考场可访问、无匹配回退和管理员冲突处理。覆盖桌面与手机布局、进入/切换/返回前台/每分钟检查；不通过调用页面内部函数代替用户操作。
- 实现阶段运行相关集成测试与项目类型检查；本规格阶段只校验文档，不宣称功能测试已经通过。

## Out of Scope

- 外部个人日历同步、邮件、短信或系统推送提醒。
- 自动修改学校邮箱、创建学校目录账号，或用姓名拼音取代现有认证机制。
- 拼音模糊匹配后静默认定身份、自动合并有冲突学生、猜测缺失的中文姓名或年级。
- 向学生隐藏其他考场，或改变现有座位表访问权限。
- 用应考身份强制锁定“我的考试”，持续覆盖用户勾选，或因座位删除自动移除已选考试。
- 提醒未发布草稿、对所有未选择考试持续发送座位变化提醒。
- 新建一套考试排程或座位分配算法；本功能整理和关联已有安排。

## Further Notes

- 本规格综合本次已确认对话；新规则替代“每次登录都覆盖选择”“隐藏其他考场”等早期设想。它扩展现有手动我的考试流程。实施与验收记录见 [student-matching-setup.md](student-matching-setup.md)。
- 实施前从部署配置取得实际学校域名，不硬编码讨论示例。学校特有拼写或无法符合邮箱格式的特殊账号按已确认规则跳过自动同步，仍能手动使用。
- 实施前的登录会话不保存邮箱，座位无学生 ID 和独立年级，因此需兼容迁移已有账号、批次、座位与个人选择。既有未完整匹配的记录仍可正常展示，由管理员补充后参与关联。
- 实现应保留当前工作区已有改动，避免把同时进行的账号与考试功能修改误当成本规格的已完成内容。
